= Eine Storage VM auf ein anderes FSx for ONTAP Dateisystem replizieren
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
Die Replikation einer Storage VM auf ein anderes FSx for ONTAP Dateisystem in NetApp Workload Factory bietet eine zusätzliche Schutzebene für den Datenzugriff im Falle eines Datenverlusts. Bei diesem Vorgang werden alle Volumes einer Storage VM auf ein anderes FSx for ONTAP Dateisystem repliziert.

.Bevor Sie beginnen
Um eine Storage-VM auf ein anderes FSx for ONTAP File System zu replizieren, muss eine Verknüpfung hergestellt werden. link:create-link.html["Erfahren Sie, wie Sie einen bestehenden Link verknüpfen oder einen neuen Link erstellen und verknüpfen"^]. Nach der Verknüpfung kann zu diesem Vorgang zurückgekehrt werden.

.Schritte
. Melden Sie sich bei der link:https://console.netapp.com["NetApp Console"^] an.
. Im Menü image:workloads-menu-icon.png["Das Hamburger-Menüsymbol wird für die Navigation zu Workloads, dem Menüpunkt für Workload Factory, verwendet"] ist *Workloads* > *Storage* > *FSx for ONTAP* auszuwählen.
. In *FSx for ONTAP* wird im Aktionsmenü des Dateisystems mit der zu replizierenden Storage-VM die Option *Manage* ausgewählt.
. In der Dateisystemübersicht erfolgt unter Storage VMs die Auswahl von *Manage*.
. Auf dem Bildschirm „Manage storage VMs“ erfolgt die Auswahl von *Advanced actions* > *Replicate storage VM* im Aktionsmenü der zu replizierenden storage VM.
. Auf der Seite „Daten replizieren“ sind unter „Replikationsziel“ die folgenden Angaben erforderlich:
+
.. *FSx for ONTAP file system*: Wählen Sie Anmeldeinformationen, Region und FSx for ONTAP file system name für das Ziel-FSx for ONTAP file system aus.
.. *Name der Storage VM*: Die Auswahl der Storage VM erfolgt im Dropdown-Menü.
.. *Volume name*: Der Name des Ziel-Volume wird automatisch im Format `{OriginalVolumeName}_copy` generiert.
.. *Tiering-Richtlinie*: Auswahl der Tiering-Richtlinie für die im Ziel-Volume gespeicherten Daten.
+
_Auto_ ist die standardmäßige Tiering-Richtlinie, wenn Sie ein Volume in der Workload Factory Managementplattform erstellen. Weitere Informationen zu Volume-Tiering-Richtlinien sind unter link:https://docs.aws.amazon.com/fsx/latest/ONTAPGuide/volume-storage-capacity.html#data-tiering-policy["Volume-Speicherkapazität"^] in der Dokumentation zu Amazon FSx for NetApp ONTAP verfügbar.

.. *Maximale Transferrate*: Für *Begrenzt* ist das maximale Transferlimit in MB/s anzugeben. Alternativ steht *Unbegrenzt* zur Auswahl.
+
Ohne eine Begrenzung könnten Netzwerk- und Applikations-Performance sinken. Wir empfehlen jedoch eine unbegrenzte Transferrate für FSx for ONTAP Dateisysteme für kritische Workloads, beispielsweise solche, die primär für die Notfallwiederherstellung verwendet werden.



. Unter Replikationseinstellungen sind die folgenden Angaben erforderlich:
+
.. *Replikationsintervall*: Bestimmt, wie oft Snapshots vom Quell-Volume auf das Ziel-Volume übertragen werden.
.. *Langzeitaufbewahrung*: Optional können Snapshots für die Langzeitaufbewahrung aktiviert werden.
+
Wenn Sie die Langzeitaufbewahrung aktivieren, erfolgt die Auswahl einer vorhandenen Richtlinie oder die Erstellung einer neuen Richtlinie, um die zu replizierenden Snapshots und die Anzahl der aufzubewahrenden Snapshots festzulegen.

+
... Für *Choose an existing policy* ist eine bestehende Richtlinie aus dem Dropdown-Menü auszuwählen.
... Für *Neue Richtlinie erstellen* sind die folgenden Angaben erforderlich:
+
.... *Richtlinienname*: Geben Sie einen Richtliniennamen ein.
.... *Snapshot-Richtlinien*: Wählen Sie in der Tabelle die Häufigkeit der Snapshot-Richtlinie und die Anzahl der aufzubewahrenden Kopien aus. Sie können mehrere Snapshot-Richtlinien auswählen.






. *Erstellen* auswählen.


.Ergebnis
Alle Volumes innerhalb der Storage VM werden auf das Zieldateisystem repliziert.
